# Journal du 9 novembre 2026

## Inscrit sans compte à une activité seule

Signalement du commanditaire (téléphone) : « déjà inscrit », mais toujours le bouton d'inscription. Cause : sans connexion, la page ne lit aucune inscription ; et la salle exige une connexion, alors que le courriel de confirmation y menait. Une personne inscrite sans compte à une activité seule n'avait donc aucun moyen d'entrer. Les journées avaient déjà leur lien personnel.

Option A choisie par le commanditaire (lien personnel, comme les journées) :

- Modèle : `programme.registrations.manage_token_hash` (empreinte SHA-256, jamais rendue). Migration `2026-11-09-entree-sans-compte-activite`.
- `sinscrire` sans compte : jeton neuf et confirmation mise en file dans la transaction (`SEND_REGISTRATION`, `carries_secret`). Déjà inscrit : nouveau jeton, courriel renvoyé, `AlreadyRegistered { registration: None }`. Fuite colmatée : l'API rendait la ligne d'inscription, réponses comprises, à qui tapait une adresse.
- La confirmation du consommateur des avis s'efface quand un lien personnel existe.
- `GET /sessions/{id}/meeting/access` accepte `X-Manage-Token`, qui prime sur la session ; première entrée notée.
- Site : page `/programmations/…/direct` (`EventLiveLinkEntry`, partagé avec la journée), billet « Inscription confirmée » et « Recevoir de nouveau mon lien », fait retenu dans le navigateur (`localStorage`), textes de la fenêtre et de la salle.
- Limite assumée, comme les journées : un rappel ne porte pas le jeton (la base ne le garde que haché). Il mène à la salle, qui invite à reprendre son adresse pour recevoir le lien.
- `2026-11-09-renvoi-liens-sans-compte` donne leur lien aux inscrits existants : **envoie de vrais courriels, à jouer sur accord**.

Contrôles : clippy propre, tests des nouveaux chemins verts, 136 tests du site, types, build. `.sqlx` préparé sur la base d'essai, car la base de développement est en retard sur le modèle (`platform.ops_log` absente) ; cinq fichiers au plan différent restaurés, seules les requêtes modifiées changent. `tableau.rs` : `p.id AS "id!"`, le vérificateur la jugeait nullable sur cette base.

15 tests échouent dans `programme` et `engagement`, sans rapport avec ce travail (compteurs de routes et de règles, confirmations de courriels ajoutées aux rappels, champs servis) : dette à solder. `harnais` corrigé (27 types de notification).
